# M3.4 Trackers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A campaign keeps named numbers the story needs between sessions, such as V5 Hunger. `tracker_add`, `tracker_adjust` and `tracker_remove` change them and log each change like `set_chaos`. The brief and the recap show them, and system prompt rule 13 has the DM ask before tracking something new and announce every change.

**Architecture:** A new `tracker` table (migration V4) and a new package `dev.tableteller.tracker`, holding the `Tracker` record, `TrackerRepository` and `TrackerTools`. `TrackerTools` follows `OracleTools.setChaos`:
1. check the input
2. in one transaction, resolve the campaign and lock its row
3. make the change
4. append one roll-log row with empty dice

`CampaignBriefs` and `SessionTools` read the trackers, so `campaign_open`, the brief resource and the recap show them.

**Tech Stack:** M3.3's stack, unchanged: Java 21, Spring Boot 4.1.1, Spring AI 2.0.1 (MCP SDK 2.0.0), Jackson 3, Flyway, PostgreSQL 16, JUnit 5 + AssertJ, Testcontainers. No new dependencies.

## Global Constraints

- Every M1–M3.3 constraint still holds:
  - Run Gradle with `JAVA_HOME=/c/Users/sefim/.jdks/corretto-21.0.10`, and Docker must be running.
  - All randomness goes through `RandomSource.between`; the tracker tools roll nothing.
  - Bad input throws `IllegalArgumentException` whose message says what is wrong and what is allowed.
  - No `@SpringBootTest`, and no text from published games in the repo.
- Do not run `bootJar` and do not touch `build\libs`: Claude Desktop runs that jar and locks it.
- A tool checks its own input before it resolves `campaign`, so input errors come before campaign errors. A rejected call, including one rejected after the campaign is resolved, writes nothing: no roll-log row and no change to the tracker.
- Each tracker tool call writes exactly one roll-log row, with empty dice, in the same transaction as its change, after `state.lock`.
- Values, limits and deltas are whole numbers within ±1,000,000, the same bound as `roll` (`ROLL_LIMIT`).
- Tracker names are trimmed and match ignoring case through SQL `lower()`; the stored spelling is the first one written.
- An optional text (`note`) that is null, empty or only spaces counts as not given.
- Summaries and messages other than the ones this plan lists do not change, including the brief's and the recap's `summary` lines.
- `tools/list` grows from 19 to 22 tools; `prompts/list` stays at 5.
- The JSON keys are `min` and `max`; the columns are `min_value` and `max_value`.

## Review Focus

1. **Hunger at its max:** `+1` at 5 of 5 must reply `Stopped at the max, 5.` and `clamped: true`. In V5 that is when the Beast breaks loose, so a silent `5 → 5` would hide it. Test: Task 2 `adjustStopsAtTheLimitsAndSaysSo`.
2. **A misspelled name never starts a second tracker:** `tracker_add` of `голод` while `Голод` exists is an error, and so is `tracker_adjust` of an unknown name, which lists the tracked names. Tests: Task 2 `addRejectsANameAlreadyTracked` and `adjustRejectsBadInput`.
3. **A rejected change leaves no trace:** an adjust past ±1,000,000 on a side with no limit leaves the value as it was and writes no row. Test: Task 2 `adjustPastAMillionWithoutALimitIsAnError`.
4. **Cyrillic over stdio:** the playtests are in Russian, so `Голод` and the reason `Проверка Пробуждения: 4` must come back intact and match `голод` ignoring case. Test: Task 2 `trackersOverStdio`.
5. **Remove and start over:** after `tracker_remove`, the same name can be added again, and the removed tracker is gone from the brief. Test: Task 2 `removeStopsTrackingAndKeepsTheHistory`.

### Task 2: tracker_add, tracker_adjust and tracker_remove

**Files:**
- Create: `tracker/TrackerTools.java`, `src/test/java/dev/tableteller/tracker/TrackerToolsTest.java`
- Modify: `TestOracle.java`, `StdioEndToEndTest.java`

**Interfaces:**
- Consumes: Task 1's `Tracker`, `Tracker.limits()` and `TrackerRepository`.
- Produces: `@Component public class TrackerTools(TrackerRepository trackers, CampaignResolver resolver, OracleStateRepository state, RollLogRepository rolls, TransactionTemplate transactions)`. Its javadoc says the tools write one roll-log row each, like `set_chaos`, and roll nothing.
- Produces: `public record TrackerResult(@JsonProperty("roll_id") String rollId, Tracker tracker, String summary)` for add and remove, and `public record AdjustResult(@JsonProperty("roll_id") String rollId, Tracker tracker, @JsonProperty("previous_value") int previousValue, boolean clamped, String summary)`.

**`trackerAdd(String campaign, String name, Integer value, Integer min, Integer max, String note) → TrackerResult`**
- Tool description: "Start tracking a number the story keeps, such as Hunger, ammunition or a countdown, once the player agrees. Give it limits if it has them, and put the rule for how it changes in note."
- Parameters:
  - `name`: required, "What is tracked, e.g. Hunger; one tracker per name in the campaign, ignoring case"
  - `value`: required, "Its value now, a whole number"
  - `min`: optional, "The lowest it can go, if it has a lowest"
  - `max`: optional, "The highest it can go, if it has a highest"
  - `note`: optional, "How it changes, e.g. the house rule; shown in the brief and the recap, never read by the server"
- Input checks, in this order, all before the campaign is resolved:
  1. `name must not be blank`
  2. `value is required`
  3. `value must be within ±1,000,000; got 1000001`, and the same message for `min` and `max`
  4. `min must be less than max; got min=5, max=5`
  5. The value against its limits: `value 7 is outside 0 to 5`, or `value -1 is below the min, 0`, or `value 6 is above the max, 5`
- In the transaction, a taken name gives `'Голод' is already tracked (1, 0 to 5); change it with tracker_adjust, or tracker_remove it to start over`. For a tracker with no limits, the parentheses hold only the value, as in `(4)`.
- The row has tool `tracker_add`. Its inputs are `name` (trimmed), `value`, and whichever of `min`, `max` and `note` were given. Its result is the same fields as the stored tracker.
- Summary: `"Tracking %s: %d%s."` (name, value, `limits()`).

**`trackerAdjust(String campaign, String name, Integer delta, String reason) → AdjustResult`**
- Tool description: "Change a tracked number by delta and say what changed it; announce the change to the player. It stops at the tracker's limits and says so."
- Parameters:
  - `name`: required, "The tracker's name, matched ignoring case"
  - `delta`: required, "How much to add; negative to take away; not 0"
  - `reason`: required, "What changed it, e.g. Rouse check 4"
- Input checks, in this order:
  1. `name must not be blank`
  2. `delta must be a whole number other than 0; got 0` (`got null` when missing)
  3. `delta must be within ±1,000,000; got 1000001`
  4. For a null or blank reason: `reason must not be blank; say what changed the number, for example "Rouse check 4"`
- In the transaction, an unknown name gives `no tracker 'Hungr'; tracked: Hunger, Willpower` (in the order added), or `nothing is tracked yet; start with tracker_add`.
- The new value is the old value plus `delta`, stopped at `min` or `max` where the tracker has one. `clamped` is true when it stopped.
- On a side with no limit, a result past ±1,000,000 gives `that would make Gold 1000001, past ±1,000,000`.
- The row has tool `tracker_adjust`. Its inputs are `name` (trimmed, as given), `delta` and `reason` (trimmed). Its result is `name` (the stored spelling), `value`, `previous_value` and `clamped`.
- Summary: `"%s: %d → %d (%+d, %s)."` (stored name, old value, new value, delta, trimmed reason). When clamped, it is followed by ` Stopped at the max, %d.` or ` Stopped at the min, %d.`

**`trackerRemove(String campaign, String name) → TrackerResult`**
- Tool description: "Stop tracking a number the story no longer needs. Its history stays in the roll log."
- Parameters: `name`, required, "The tracker's name, matched ignoring case".
- `name must not be blank`, then the unknown-name messages above.
- The row has tool `tracker_remove`. Its inputs are `name` (trimmed, as given), and its result is `name` (stored) and `value` (the last value).
- Summary: `"Stopped tracking %s at %d."`
