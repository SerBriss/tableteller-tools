# M3 Journal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The campaign journal: `journal_write`, `journal_search`, `journal_get`, `roll_history`, `session_start` / `session_end`, the three resources and the three prompts, so canon and recaps live outside the chat window.

**Architecture:** A Flyway migration adds `journal_entry` and `session_log`. New `journal` and `session` packages follow M2's shape: a `JdbcClient` repository with plain SQL, and a tools class whose writes run in one `TransactionTemplate` transaction that locks the campaign row first. Journal-side tools write no roll-log rows. Resources and prompts are Spring AI `@McpResource` / `@McpPrompt` methods on two small components; prompts are fixed instruction text with no side effects.

**Tech Stack:** M2's stack, unchanged: Java 21, Spring Boot 4.1.1, Spring AI 2.0.1 (MCP SDK 2.0.0), Jackson 3, Flyway, PostgreSQL 16, JUnit 5 + AssertJ, Testcontainers. No new dependencies.

**Spec:** `docs/SPEC.md` (v0.5). Read "Domain model", "Journal tools", "Resources and prompts", "Persistence schema" and the v0.5 decisions before starting.

**Branch:** `m3-journal`, cut from `master`.

## Global Constraints

- Every M1 and M2 constraint still holds: run Gradle with `JAVA_HOME=/c/Users/sefim/.jdks/corretto-21.0.10`; Docker must be running; all randomness goes through `RandomSource.between`; enums seen outside the code use lowercase constants equal to their wire value; tool output fields are snake_case via `@JsonProperty`; bad input throws `IllegalArgumentException` whose message says what is wrong and what is allowed; no `@SpringBootTest`; no text from published games in the repo.
- **Journal-side tools** (`journal_*`, `session_*`, `roll_history`, plus M2's `campaign_*` and `list_*`) write no roll-log rows, and every one except `campaign_create` and `campaign_open` calls `ActiveCampaign.require()` first.
- Journal-side tools that write (`journal_write`, `session_start`, `session_end`) run inside `transactions.execute(...)` and call `state.lock(campaignId)` first, so they serialize with oracle tools and read the current scene number from the locked row.
- Tool parameter names are the spec's snake_case names, used verbatim as Java parameter names (`String entry_id`, `Integer last_n`, `String open_questions`).
- Titles are trimmed and compare ignoring case (Postgres `lower()`); the stored spelling is the first one written.
- Timestamps in output are `Instant` fields; Jackson 3 writes them as ISO-8601 strings.
- `TestDatabase.reset()` truncates all six tables. Every test class that touches the database calls it in `@BeforeEach`.
- The e2e tool-list test (`StdioEndToEndTest.listsTheOracleToolsWithLowercaseOdds`) lists every tool exactly. Each task that adds a tool adds its name there; M3 ends at 18 tools.

## Review Focus

1. **`session_start` called twice in a row** (the prompt and system-prompt rule 7 both ask for it): the first, empty session becomes abandoned, the second recap still shows scenes and lists, and nothing errors. Test: Task 5 `startingTwiceAbandonsTheFirstSession`.
2. **Search text with quotes, backslashes or tsquery operators** (`O'Brien`, `"Varo"`, `varo:*`, `a & | ! ( )`, `back\slash`): no Postgres syntax error ever reaches the DM; `O'Brien` finds "O'Brien", and pure punctuation is a clear error. Test: Task 3 `queryPunctuationNeverReachesPostgresAsSyntax`.
3. **Cyrillic titles and inflected names:** writing npc ` таверна ` replaces `Таверна` and keeps that spelling; searching `вар` finds both `Варо` and `Варом`. Tests: Task 2 `replacesIgnoringCaseIncludingCyrillic`, Task 3 `prefixMatchesInflectedCyrillicNames`.
4. **Another campaign's rows:** `journal_get`, `journal_search`, `roll_history` and `session_start` never read or change another campaign's entries, rolls or sessions. Tests: Task 2 `getNeverReturnsAnotherCampaignsEntry`, Task 3 `searchStaysInTheOpenCampaign`, Task 4 `onlyTheOpenCampaignsRolls`, Task 5 `sessionsBelongToTheirCampaign`.
5. **The client restarts mid-session:** the open session is in the database, so after a restart and `campaign_open`, `session_end` ends it and the summary is not lost. Test: Task 8 `openSessionSurvivesARestart`.

### Task 3: journal_search

**Files:**
- Create: `src/main/java/dev/tableteller/journal/SearchHit.java`
- Modify: `journal/JournalRepository.java`, `journal/JournalTools.java`, `StdioEndToEndTest.java` (tool list)

**Interfaces:**
- Produces: `public record SearchHit(@JsonProperty("entry_id") UUID entryId, JournalKind kind, String title, String excerpt, List<String> tags, @JsonProperty("scene_number") int sceneNumber)`, with `static String excerpt(String body)`: the first 300 code points of the body, plus `…` when the body is longer. A surrogate pair is never split.
- Produces on `JournalRepository`:
  - `static List<String> words(String query)`: the runs of letters and digits in the query (regex `[\p{L}\p{N}]+`), in order
  - `List<SearchHit> search(UUID campaignId, List<String> words, JournalKind kind, int limit)`. `kind` null means every kind. Order: `ts_rank(search, q)` descending, then `updated_at` descending, then title.
- Produces on `JournalTools`:
  - `public record SearchResult(String query, List<SearchHit> entries, String summary)`, where `query` is the trimmed query.
  - `@McpTool(name = "journal_search") SearchResult journalSearch(String query, JournalKind kind)`. Description: "Search the journal before naming or describing anything that may already exist. Every word must match the start of a word in an entry's title or body." `kind` is optional. It asks the repository for 21 hits and returns at most 20.

The query reaching Postgres is built from `words` only, so no user punctuation reaches the tsquery parser:

```sql
-- words [inn, varo] → 'inn:* & varo:*'
... where e.campaign_id = ? and e.search @@ to_tsquery('simple', ?) ...
```

Use the same `to_tsquery('simple', ?)` expression in `ts_rank`. Add `and e.kind = ?` only when `kind` is given.

| Case | Message or summary |
| --- | --- |
| blank query | `query must not be blank` |
| no letters or digits (`!!!`) | `query needs at least one letter or digit; got '!!!'` |
| none | `No entries match 'varo'; if it is new, record it with journal_write.` |
| one | `1 entry matches 'varo'.` |
| several | `3 entries match 'varo'.` |
| 21 or more | `More than 20 entries match 'rat'; showing the best 20. Add words or pass kind to narrow it.` |
