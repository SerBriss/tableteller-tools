# M2 State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Campaign state that survives restarts: Postgres-backed campaigns, scenes, threads and characters lists, random events, and a persistent roll log, with `fate_check` returning the full random event.

**Architecture:** Flyway creates four tables in a local Postgres 16. Repositories use Spring's `JdbcClient` with plain SQL. Every oracle tool call runs in one `TransactionTemplate` transaction that locks its campaign row, changes state and appends its roll-log row. A real `ActiveCampaign` holder replaces M1's implicit campaign: `campaign_create` and `campaign_open` set it, and every other tool fails without it. Random events roll the `default` focus table, pick a weighted target from the lists, and add an `actions` meaning pair.

**Tech Stack:** M1's stack (Java 21, Spring Boot 4.1.1, Spring AI 2.0.1, Jackson 3, JUnit 5 + AssertJ, Gradle 9.8.1) plus `spring-boot-starter-jdbc`, `spring-boot-starter-flyway` (Flyway 12.4), the PostgreSQL driver 42.7, and Testcontainers 2.0.5 (`testcontainers-postgresql`). All versions come from the Boot BOM.

**Spec:** `docs/SPEC.md` (v0.4). Read "Architecture", "Domain model", "Oracle tools", "Journal tools" (campaign and list rows only), "Table data and licensing" and "Persistence schema" before starting.

**Branch:** `m2-state`, cut from `master`.

## Global Constraints

- Every M1 constraint still holds. In particular: there's no `java` on PATH, so run Gradle with `JAVA_HOME=/c/Users/sefim/.jdks/corretto-21.0.10`; all randomness goes through `RandomSource.between`; enums seen outside the code use lowercase constants equal to their wire value; tool output fields are snake_case via `@JsonProperty`; bad input throws `IllegalArgumentException`, whose message says what is wrong and what is allowed; there is no `@SpringBootTest`; no text from published games goes in the repo.
- Docker must be running for the tests. Tests share one Testcontainers `postgres:16-alpine` container per test run, through `dev.tableteller.support.TestDatabase`, and every test class that touches the database calls `TestDatabase.reset()` in `@BeforeEach`.
- Data access uses Spring `JdbcClient` and plain SQL in `@Repository` classes, with no JPA. Migrations live in `src/main/resources/db/migration`.
- **Oracle tools** (`roll`, `fate_check`, `meaning`, `set_chaos`, `random_event`, `scene_check`, `end_scene`) all follow the same pattern: validate input, then `transactions.execute(...)`, which runs `campaign.require()` and `state.lock(campaignId)`, does the work, appends exactly one roll-log row and returns. A rejected call writes nothing.
- **Journal-side tools** (`campaign_create`, `campaign_open`, `list_add`, `list_update`, `list_get`) write no roll-log rows.
- Every tool except `campaign_create` and `campaign_open` requires an open campaign. `ActiveCampaign.require()` throws `IllegalArgumentException` with one of two messages:
  - `No campaign is open, and none exist yet. Create one with campaign_create.`
  - `No campaign is open. Open one with campaign_open: <names, sorted ignoring case, joined by ", ">`
- Tool parameter names are the spec's snake_case names, and the Java parameters use them verbatim (`String expected_setup`). Spring AI takes schema names from parameter names, and Boot's Gradle plugin compiles with `-parameters`.
- Names are trimmed. Campaign names and list titles compare ignoring case, and the stored spelling is the one from the first write.
- The e2e tool-list test (`StdioEndToEndTest.listsTheOracleTools`) lists every tool exactly. Each task that adds a tool adds its name there.

## Review Focus

1. **The database is down when the client starts the server:** the server must exit with a non-zero code, print nothing on stdout, and log the connection failure. It must never answer `initialize` and then fail on every call. Test: Task 9 `serverExitsWhenTheDatabaseIsDown`.
2. **A restart:** chaos, scenes, lists and roll ids survive it, but the open campaign doesn't, so tools fail with the campaign list until `campaign_open`. Test: Task 9 `stateSurvivesARestartButTheOpenCampaignDoesNot`.
3. **A random event targeting a list whose entries are all closed or removed** must treat the list as empty and return `new: true`, never pick a closed thread. Test: Task 6 `closedEntriesAreNeverPicked`.
4. **Cyrillic names compared ignoring case:** a campaign named `Пепел` must open as `пепел`, and `тайна` must match `Тайна` on a list. This relies on Postgres `lower()` under the container's UTF-8 locale. Tests: Task 4 `titlesMatchIgnoringCaseIncludingCyrillic`, Task 8 `opensByNameIgnoringCaseAndSpaces`.
5. **Names with stray spaces or different case** (`"  ashfall "`, `"find THE heir"`) must reach the existing campaign or entry, never create a near-duplicate. Tests: Task 2 `createRejectsANameThatDiffersOnlyInCaseOrSpaces`, Task 4 `addRejectsATitleThatDiffersOnlyInCaseOrSpaces`.
